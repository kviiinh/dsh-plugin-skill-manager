# dsh-plugin-skill-manager

DSH 的技能管理器：把散在六个扫描根里的技能**按技能目录摊开**、就地管理，从自定协议的
市场里**搜索安装**（自己选装到哪个技能根），从本地**拖拽/点击导入**已有技能，再用
`/skill/<技能目录>/<技能>` 精确调用任意一份。

- 宿主半边：Cordis 插件（`index.js`，`name = 'skill-manager'`，`inject = ['webServer','connection']`）
- 客户端半边：侧栏页面（`client.js`，`panel id = skills`）
- 两者只通过**同源 HTTP 路由**通信（第三方客户端插件拿不到 typert Remote）

## 界面

侧栏多一个 **技能** 页（与「插件」页同级）。**顶栏固定不变**：最左是标题 `技能管理器`，
紧挨着三个页签「已安装 / 技能市场 / 回收站」，右端是**全页唯一的 `刷新`**。
刷新刷新的是**当前页签**：

| 当前页签 | 点「刷新」做什么 |
|---|---|
| 已安装 | 重扫技能文件夹、重建注册表（`/skill-manager/catalog?refresh=1`） |
| 技能市场 | 重跑当前那次搜索（搜过才重跑），并刷新已装列表 |
| 回收站 | 重读目录数据（回收站台账在里面），不白扫一遍技能目录 |

`设置`（市场地址等）属于技能市场，所以放在**市场页搜索框的右边**，点开是**设置弹窗**。

| 页签 | 内容 |
|---|---|
| 已安装 | 内容区第一行是工具栏：`技能目录` / `分类` 两个**带边框的筛选字段**（`.5px` 边、32px 高、圆角 md，DSH 搜索框那种 `.wrap`，两个筛选器靠各自边框分界；hover 时边框加深 + 浅底）+ 右侧 `导入本地`（**实心主按钮**，黑色）；点开是**自制浮层**（不用原生 `<select>`，因为它的弹出面板样式改不动）：`--dsw-alias-bg-base` **不透明底**（否则会透出下面的卡片文字）、圆角、`--dsw-elevation-prominent` 阴影、4px 内距，每项 34px；**选中项只靠右侧对勾**，底色只用于鼠标悬停/键盘高亮；展开时箭头转 180°；下一行是 `共 N 个技能 · 按优先级推算`，筛选中时写成 `共 M / N 个技能 · <技能目录> · <分类>`；主体是**卡片网格**（每行 6 张、可视 4 行，行高 **264px**（原 132px 的 200%），超出滚动），卡片悬浮时按 DSH 的 `interactive-bg-hover` 上底色 |
| 技能市场 | `[搜索框] [搜索] [设置] …… [安装位置▾]`；按钮层级跟 DSH 一致：`搜索` 是**描边按钮**（白底），`设置` 是**实心主按钮**（`button-primary-fill` 底色、反白字）；下面是搜索结果（每条带 `安装`）与已装列表（每条带 `卸载`，只列市场装的） |
| 回收站 | 顶部是 `共 N 个技能` 与右侧的 `清空回收站`（红色）；下面是**一行一条**（DSH 插件列表那种 0.5px 细线分隔的行，不是一叠卡片）：第一行名字 13.5/500，第二行来源根（灰底小标签）+ 删除时间 12.5 二级文字色（**不显示技能路径**，行内距按两行内容收到 8px）；每行右侧 `还原`（白描边）/ `彻底删除`（红）。两个危险操作都走 DSH 的确认弹窗（描边「取消」+ **实心红**确认，宽度用 DSH 默认的窄弹窗，不跟导入/设置一样宽）；清空时若个别条目正被别的程序占着（杀毒/索引扫描），用黄字说明"删了几个、哪几条没删掉"，不整批失败 |

**卡片版式**（自上而下，用户定的）：

1. **技能名 + 启停开关**同一行：名字占满左侧（永远一行、超出打省略号），开关靠右
   （开启色 **`#00CC00`**，关 = 灰）。名字**只有真的被截断时**悬浮才出气泡显示完整名称，
   没截断就什么提示都不显示（卡片根上不挂 `title`，否则悬浮名字会冒出整段介绍）。
   名称气泡与介绍气泡是同一个组件（`HoverBubble`），**不用原生 `title`**——原生 tooltip 是浏览器画的
   （系统灰底），跟 DSH 的气泡对不上；
   **不再显示生效/无效状态**（详情弹窗里也不显示，状态只体现在开关是开还是关）；
2. 标签行（**技能目录 + 分类**）—— **左对齐**；11px 小标签，颜色由文字散列到 8 组色相
   （文字 75% 饱和、底色 20% 同色），不同目录/分类颜色不同；没有分类的显示「未分类」；
   标签被省略时悬浮出 DSH 气泡显示全称；
3. 一条 `0.5px` 分割线；
4. 分割线以下**全是技能介绍**（最多 7 行 = 7 × 18px 显式 `max-height`；只靠
   `-webkit-line-clamp` 在 flex 子项里 Chrome 不按它截断，会露出半行字）。
   **只有显示不全时**悬浮才出气泡显示完整介绍，气泡照 DSH 的 `Tooltip`（`_bubble_12mhf_1`）：
   `--dsw-alias-tooltip-bg` 深底 + 反白字、13/20、小圆角、**`max-width:25vw`**
   （默认气泡是 `50vw`，介绍这个按用户要求收窄成一半）、
   `position:fixed`（卡片有 `overflow:hidden`，fixed 才不会被裁掉）、`pointer-events:none`；
   出现后会量一次自身尺寸，**把坐标夹进视口**：靠右一列的卡片不会把气泡顶出右边，
   下方放不下时自动翻到触发元素上方（`clampTipPosition`）；
5. 卡片最下方：`删除` `详情` —— **右对齐**，常显不用悬停。

卡片文字照 DSH 内置插件卡片：标题 14px/500、描述 13px/18 三级文字色。

**`/skill` 提示源是"懒注册"的**：`inputTriggers` 服务可能比本插件晚就绪
（客户端插件按加载顺序 apply），所以不能用 `ctx.get` 抓一次就完事——拿不到就轮询等（400ms 一次，
最多 20 秒），拿到再注册；注册本身抛错会打一条 `[skill-manager] /skill 提示源注册失败` 的告警，
一直等不到会打 `等不到 inputTriggers 服务`。这两条日志是用来回答"为什么 / 菜单里没有 /skill/"的。

**界面上也不使用原生 `<select>`**：它的弹出面板是操作系统画的（蓝条高亮），跟 DSH 完全不是一套，
而且没法上样式。**所有单选下拉都调用同一个组件 `FilterSelect`**（共 6 处：已安装页的两个筛选器、
详情页的「技能目录」、导入弹窗的「导入到」、技能市场的「安装位置」、设置的「导入目标」；
详情页那处用 `renderValue` 把值渲染成标签、用 `options[].disabled/note` 标出只读根）：
字段框 `.5px` 边 / 32px / 圆角 md / 标签在框内 + 右侧 chevron，面板 4px 内距、`--dsw-elevation-prominent`
阴影、每行 34px、hover 上底色、**选中项只靠右侧对勾**。面板用 `position: fixed`
（弹窗里也不会被裁掉；注意 fixed 下 `min-width:100%` 会按视口算，必须显式写 0）。

详情页的**分类是多选**，所以用另一套面板（左侧方框 + 铅笔改名 + 新增输入）；
它的触发器做成了**和单选一样的字段框**（值用逗号分隔的纯文本、不再用彩色标签），
面板里的行也有 hover 底色（`.dsh-sm-pop-row:hover`，以前只写了 CSS 忘了挂类名）。

**界面上不使用浏览器原生 `title` 提示**：原生 tooltip 是系统灰底样式，和 DSH 完全不是一回事。
所有悬浮提示（技能名、技能介绍、标签、筛选项、开关、按钮、徽章、弹窗关闭图标、导入弹窗里的路径与摘要）
统一走 `HoverBubble`
——`--dsw-alias-tooltip-bg` 深底 + 反白字、13/20、`padding:3px 7px`、小圆角、`max-width:50vw`、
`position:fixed`、`pointer-events:none`，出现后按自身尺寸夹进视口。
其中"信息型"提示（名字/介绍/标签/筛选项/路径/摘要）只在**真的显示不全**时出现；按钮与开关的说明性提示总能出现
（开关的解释挂在外面那层 span 上，所以禁用状态也能看到）。

**技能目录筛选**（已安装页）：下拉里每一项都带该目录的技能数（`user-agents（4）`），
`插件提供` 单独一档；随包分发的根有好几个、标签都叫 `bundled`，重名时补上路径尾部
（`bundled · x/bundle-a（0）`），否则下拉里会出现两个一模一样的选项。
选过的目录在下次刷新后如果没了（配置改了、根被移除），筛选项会自动清掉，
不会卡在"这个目录下没有技能"。

**分类筛选**（已安装页，第二个下拉）：读每个技能 `metadata.category`（标量、行内数组、
逗号分隔都认），没写这个字段的归到 **`未分类`**。两个筛选是**「与」**的关系，而且**双向联动**：

- **先选目录**：分类下拉只剩该目录下真出现过的分类（各自带计数）；
  目录下一个技能都没有时分类下拉直接置灰；
- **先选分类**：技能目录下拉只剩"真的有这个分类"的目录，计数也按筛完之后的算
  （所以不会出现"挑了一个没有该分类的目录、分类被静默清掉"那种看着像不联动的情况）。

选过的目录/分类在数据变化后如果不存在了会自动清回 `全部…`，不会卡在空列表。

**一张卡片只有 3 个按钮，而且不用悬停就显示**：`删除`（红字红边的「卸载」样式，点了先弹
DSH 那样的确认框：描边「取消」+ **实心红**「删除」）、`详情`（描边白按钮）、以及右侧的
**启停开关**（照抄 DSH 的 `Switch`：36×20 轨道 + 16px 滑块，开=brand-primary）。
插件内嵌技能只读，只留 `详情`。

开关就是「生效/无效」的开关：**开 = 两个调用标记都不写，关 = `disable-model-invocation`
与 `user-invocable: false` 一起写**（宿主没有单一 `enabled` 字段，只能两个一起写；
所以"只允许用户调用"这种半开状态仍算开）。

**开关的"开"= 这个技能现在真的生效**，而不是只看两个标记：校验失败（`valid:false`）或被
同名技能遮蔽（`effective:false`）的技能，开关一律显示为**关 + 置灰不可拨**，并在 tooltip 里
说明是"校验没通过"还是"被更高优先级的技能根占了"。之前直接按标记渲染，就会出现
"灰轨道 + 滑块在右边"这种看着既开又关的样子。

**技能详情是弹窗**（点卡片或卡片上的 `详情`）：信息区照 DSH 插件详情的 facts 列表
（左右两端对齐、行间 0.5px 细线；DSH 原版行高 44px 起，这里按用户要求压到**一半**：
`min-height:22px; padding:4px 2px`）。不显示「状态」行，也没有启停开关和 `删除`
（启停与删除留在卡片上）。

**详情里可以改，但只有两处**（用户定的，别的地方一律只读）：

1. **技能目录**（单选）：**直接用统一的 `FilterSelect`**（跟已安装页筛选器同一个组件），
   框里就是当前目录名；下拉**只列真实存在的根**，只读根（例如 `bundled`）灰掉并标注「只读，不能放技能」；
2. **分类**（多选）：触发器和单选**一样是个字段框**，值用**逗号分隔的纯文本**（原来没有分类就显示 `-`），
   点开面板可以
   **勾选 / 反选、新增、改名**，**最多 5 个**（满了之后"添加"禁用、未选项不可点，面板里显示 `n/5`）；
   落到 `metadata.category`：**落盘的值逗号后不留空格**（`product,codegen`；读回来按逗号切分并 trim，老的 `a, b` 写法照样能读）。界面上的显示保持原样（`product, analysis`，逗号后带空格）。

底部从左到右：`查看 SKILL.md`（展开后变 `收起文件`）、（靠右）提示「修改后点「确定」才生效（会同时更新注册表）」
+`取消`（描边）+`确定`（**实心黑**）——提示就放在「取消」左边。
两个下拉面板宽度是原来的 80%（目录 224px / 分类 240px），`overflow-x: hidden` + 行内 `box-sizing:border-box`，
所以**不会出现左右拖动条**，铅笔与「添加」也不会贴边。多选框只用长写样式（`borderWidth/borderStyle/borderColor`）——混用 `border` 简写会让“勾选后再反勾选”时方框整块消失（真出过的 bug，已加回归用例）。
**`确定` 只有存在改动时才可点**（否则是禁用变淡的样子）；点 `取消` 什么都不写。
点 `确定` 才会真正落盘，顺序是：先写分类（同一个文件里改 `metadata.category`），
再搬目录（`move-root`：先复制到目标根并逐文件校验，再删原位置，删不掉会回滚，
**永远只留一份**），最后 `refresh=1` 重建注册表（`/` 菜单与下拉立刻看到新状态）。

> UI 上不再提供「重命名 / 复制到别的根」：宿主路由与动作仍然保留（`rename` / `copy`），
> 只是按用户要求从卡片和详情里撤掉了按钮。

弹窗宽度：详情 `min(1056px, 75vw)`；导入与设置 `min(570px, 92vw)`
（DSH 的 `Modal` 自带宽度是固定的，这里用注入的类名覆盖）。

界面用的是 **DSH 自带的 UI 原子**（`@deepseek-ai/dsh-client-ui-primitives` 的
`Button` / `Tag` / `Modal` 与图标，含刷新图标）；拿不到这个模块时自动退回自带的 HTML
版本（刷新/关闭图标内联的是 DSH 同一份 SVG 路径数据），所以任何情况下都不会"整页空白"。

跨主题的一致性靠**注入一小段 CSS 补丁**（`DIALOG_CSS`）：开关、危险按钮、状态点、
详情 facts 列表这四样在 DSH 的 UI 原子里没有对外导出，就照抄宿主自己的样式表
（`PluginManagerPage.module.css` / `Switch.module.css` 的取值与结构），
再挂到 `dsh-sm-*` 这几个类名上；颜色一律走 `--dsw-alias-*` token，缺 token 时才用兜底色。
筛选下拉同理，但**没法用原生 `<select>`**（弹出面板由浏览器绘制，样式改不动），
所以自己做了一个「按钮 + 浮层列表」，DOM 结构与尺寸照 DSH 的 `.Z9Jnlq_menu` / `.Z9Jnlq_item`：
点击触发器展开、点外部或 Esc 收起、当前项右侧打勾。

### 三路导入

1. **市场安装**：搜索 → 选安装位置 → `安装` → **确认弹窗**（列出 manifest 的文件清单与
   大小、包摘要、目标根）→ 点确认才真的落盘。这是宿主的**两步**设计：第一次请求只回清单，
   第二次带 `confirm: true` 才写盘，避免"点一下就把远端内容写进技能根"；
2. **导入本地**：弹窗里只做两件事，界面上只显示这次选中/导入的路径与结果——
   - **拖拽**技能文件夹（或单个 `.md`）进来，松手选中。浏览器里拖进来的文件
     **拿不到本地绝对路径**（Electron 32+ 也移除了 `File.path`），所以点「导入」时由界面
     把内容读成 base64 交给 Host 的 `/skill-manager/import-upload` 落盘；目录用
     `webkitGetAsEntry` 递归展开；
   - **点击**拖拽区 → 浏览本机目录：优先调 DSH 自己的选目录（桌面端就是系统文件夹对话框），
     选中只填好路径；这台机器没有该系统能力时，才展开内置的本机目录列表（同样是用户点开才出现）。

   选好之后点 **`导入`** 才真的写盘。弹窗里可以选 **`导入到`** 哪个技能根（默认优先用户级根、
   会记住上次的选择，设置弹窗里也能改）；遇到同名技能会**弹出确认框**问是否覆盖
   （取消 / 覆盖）。**导入失败时那条提示是红色的**（成功那条是普通说明色）。
   （点「覆盖」才带 `overwrite` 重试，取消就什么都不做）；
3. **直接放文件夹**：把技能目录丢进任一技能根，技能根上的文件监听会把注册表标脏，
   下一步自动重扫；也可以随时点 `刷新` 强制重扫。

### 注册表

扫描结果落盘成 `<DSH_HOME>/skill-manager/registry.json`（技能名/目录/状态/资源/时间），
`/` 菜单、下拉筛选与卡片网格都读它 —— 这样打 `/` 不需要每次重新解释技能文件夹。
只有这三种情况会重扫：`刷新`（含 `refresh=1`）、文件监听到变化、缓存超过 60 秒。

### 调用

- **`/skill/<技能目录>/<技能>`**：明确指定扫描根，**直接读那一份**（不被同名遮蔽规则覆盖）；
- `/skill/<技能>`：走 DSH 注册表（含插件内嵌技能），会被遮蔽规则影响；
- 输入框里打 `/` 会**逐级提示**：`/` → `skill/` → 技能目录 → 该目录下的技能，
  2 级补全只列 `user-invocable` 不为 false 且有效的技能；选中后插入
  `/skill/<技能目录>/<技能>`；`/<技能名>` 这个内置写法照旧可用。
- 手势**只认直接的用户输入**（`message.source.kind === 'user'`），别的来源伪造不了；
  找不到技能时返回明确的错误块，让模型如实告诉用户"不可用"，而不是编造内容。

## 安装

插件是普通 DSH profile 插件，两种装法：

**A. 从本仓库装进 profile（推荐）**

```powershell
# 1) 让 profile 认到这个包（本地路径安装 + 写 bundle 选择）
node tools/install-into-profile.mjs            # 加 --dry-run 先看要改什么
# 2) 重启 Host（DSH Desktop 退出重开，或重启 dsh web）
```

脚本默认用 PATH 上的 `dsh`；桌面版自带的 CLI 不在 PATH 时，用 `--dsh <路径>` 指过去
（例如 `--dsh "<安装目录>/resources/runtime/cli/bin/dsh.cmd"`），或设环境变量 `DSH_CLI`。

回滚：`node tools/install-into-profile.mjs --uninstall` 然后重启 Host。

**B. 开发态（符号链接，改完即测）**

把 `node_modules/dsh-plugin-skill-manager` 指向本目录，然后在 profile 的
`cordis.patch.yml` 追加：

```yaml
- insert:
    - id: skill-manager
      name: 'dsh-plugin-skill-manager'
      config:
        enabled: true
        marketUrl: ''            # 留空 = 不启用市场
```

> **改动必须完整重启 Host。** 实测：客户端 bundle（`client.js`）会被重新扫描，
> 但**宿主半边（`index.js` 等）不会热更新** —— 会出现"新界面 + 旧路由"，
> 表现为某个路由 404（存在的路由本该是 401：围栏拒绝非浏览器请求）。
> 界面因此内置了**构建标记核对**：客户端与宿主的标记不一致就显示
> "客户端与宿主半边版本不一致…请完全退出 DSH Desktop 再打开"。所以改完代码请
> **彻底退出 DSH Desktop 再打开**，不要只刷新页面。

| id | 路径 | rank | 可写 |
|---|---|---|---|
| `project-dsh` | `<项目根>/.dsh/skills` | 100 | 是 |

## 客户端 ↔ 宿主 接口

全部挂在前缀 `/skill-manager` 下，并用 `connection.requestRejection` 做**同源围栏**
（非浏览器来源一律 401，不只是校验 `Origin` 头）。

| 路由 | 方法 | 参数 | 作用 |
|---|---|---|---|
| `/catalog` | GET | `cwd`、`agentId`、`refresh=1` | 目录数据：技能、技能根、回收站、市场已装、构建标记、注册表版本与时间 |
| `/read` | GET | `cwd`、`rootId`、`name` | 读某个技能 `SKILL.md` 原文（超长截断） |
| `/action` | POST | 见下方动作表 | 所有本地管理动作 |
| `/import-upload` | POST | `files[]`（base64）、`rootId`、`overwrite`、`cwd` | 落盘拖拽/上传上来的技能内容 |
| `/browse` | GET | `path` | 本机目录列表（系统选目录不可用时的兜底浏览） |
| `/market` | GET | `q`、`limit` | 市场搜索 |
| `/market/install` | POST | `name`、`version`、`rootId`、`confirm` | 两步安装（先回清单，`confirm:true` 才落盘） |
| `/market/uninstall` | POST | `name` | 卸载市场装的技能 |

### 动作（`POST /action`）

| `action` | 载荷 | 语义 |
|---|---|---|
| `set-invocation` | `rootId`、`name`、`modelInvocable`、`userInvocable` | 写 frontmatter 的 `disable-model-invocation` / `user-invocable`，保留注释与 CRLF |
| set-categories | ootId、
ame、categories[] | 写 metadata.category（逗号分隔、最多 5 个；只动这一个键，写完复读校验，不一致自动还原） |
| move-root | ootId、
ame、	argetRootId | 把技能搬到另一个技能目录：复制到目标根并逐文件校验通过后才删源；删源失败会回滚目标，**永远不会留两份** |
| `rename` | `rootId`、`name`、**`newName`** | 改 frontmatter 的 `name` **并**把目录改成同名（先确认目标不存在再落笔） |
| `copy` | `rootId`、`name`、`targetRootId`、`overwrite` | 复制到另一个技能根（用来调优先级），目标根必须可写 |

## 市场协议

管理器只要服务端提供这三个端点（`baseUrl` 就是 `marketUrl`）：

| 端点 | 返回 |
|---|---|
| `GET /v1/skills?q=&limit=` | `{items:[{name, version, description, whenToUse?}]}` |
| `GET /v1/skills/<name>/<version>` | manifest（见下） |
| `GET <bundle.url>` | `.tgz` 包体 |

manifest 形状（`files[].sha256` 与 `files[].size` 必填）：

```json
{
  "name": "demo-skill",
  "version": "1.0.0",
  "description": "一句话说明",
  "files": [{ "path": "SKILL.md", "size": 412, "sha256": "sha256:<64hex>" }],
  "bundle": { "format": "tar.gz", "url": "/v1/skills/demo-skill/1.0.0/bundle.tgz", "sha256": "sha256:<64hex>", "size": 1234 }
}
```

包体是 `.tgz`（tar + gzip），**包内顶层必须直接是 `SKILL.md`**，且 `manifest.files[].path`
要与包内路径一一对应（推荐 `tar czf demo.tgz -C <技能目录> .`）。目录条目、`./` 前缀、
pax 扩展头、中文文件名都能正常解包；路径会先做归一化（`.` 段丢弃、`..` 拒绝），
归一化后重名的条目一律拒绝。

### 一个可用的服务端实现

仓库自带参考实现 [tools/market-server.mjs](tools/market-server.mjs)：把一个"技能目录"
（每个子目录是一个含 `SKILL.md` 的技能）直接发布成上面这套端点，包体用系统 `tar` 现打。

```powershell
node tools/market-server.mjs --dir D:\my-skills --port 8787
# 然后把它填进插件配置：marketUrl: 'http://127.0.0.1:8787'
```

它没有鉴权、没有持久化、没有签名，是**示例**不是产品；生产环境请自行加认证与签名。
端到端链路（搜索 → 安装 → 卸载）在 `test/market.test.mjs` 里有用例直接对着它跑。

**服务端必须缓存扫描结果**（参考实现里是进程级缓存 + `refresh()`）：`tar` 的 gzip 头带 mtime，
同一份目录两次打包字节可能不同；若每个请求都重新打包，"搜索时那份 manifest 的 sha256" 与
"随后下载到的包体"就会对不上，客户端会（正确地）以"技能包摘要与 manifest 不符"拒绝安装。

## 安全模型

市场内容按**不可信**处理。安装顺序（任一步失败都不落盘、不留临时目录）：

1. manifest 字段校验：`name` 必须 kebab-case；每个路径先**归一化**（`.` 段丢弃、
   `..` 一律拒绝）再判重（Windows/macOS 上大小写不敏感，Linux 上不去误拒大小写差异）；
   段内禁止 `:` 与控制字符（`:` 在所有平台都禁——Windows 上 `SKILL.md::$DATA`
   这类 ADS 别名指向同一个文件），Windows 上另外禁止 `< > " | ? *`；
   `files[].sha256` 必须是 `sha256:<64hex>`、`files[].size` 必填且为非负整数；
   必须**恰好声明一个** `SKILL.md`（大小写不敏感）；`bundle.format` 必须是 `tar.gz`；
2. **包体地址白名单**：相对地址按市场拼接；绝对地址必须落在 `marketUrl` 自己的
   origin（或 `marketAllowedOrigins` 里显式列出的 origin）；非 http(s) 协议直接拒绝；
   跳转用 `redirect: 'manual'` **逐跳校验** —— 未授权 origin 的请求根本不会发出
   （事后检查落地地址是不够的：那时对方已经收到请求了）。`marketToken` 只发给市场
   自身 origin，不会跟着请求跑到白名单里的第三方 origin；
3. 包体大小上限（`bundle.size` 若声明则与实际长度核对）；
4. `bundle.sha256` 若声明则摘要比对；
5. 归档只接受普通文件/目录：拒绝绝对路径、`..`、符号链接与硬链接，按归一化后的键
   拒绝重复条目，校验每个条目头的 checksum；目录条目（BSD/GNU tar 天然带尾斜杠）
   正常接受；空归档/非 tar 明确报错；
6. **逐个文件**核对 `sha256` 与 `size`，且要求归档路径与 manifest 声明**逐字节相等**
   （`S\u212AILL.md` 折成小写等于 `skill.md`，但它是另一个文件），声明与归档必须
   **一一对应**（缺一个、多一个、重复一个都拒绝）；落盘路径一律用**声明路径**；
7. 包内那份 `SKILL.md` 必须合法、`name` 必须与市场条目一致；
8. 在**技能根之外**（根的父目录，同一卷）建暂存目录写盘，然后按已校验的摘要
   **复读**一遍——字符串层面的去重挡不住"键不同、文件相同"的别名（NTFS ADS、
   8.3 短名、硬链接……），复读发现不一致就放弃整次安装；
9. 改名进 `<root>/<name>` 之后**再按最终位置复验一遍**（改名到落定之间任何本地
   改写都会在这里被抓到），不一致就删掉这次安装并报错；
10. 目标已存在时：**同版本同摘要、且磁盘内容逐文件复核通过**才走幂等返回
    （标记文件本身没有认证，不能只信它）；目标不是根内的真实目录（例如被换成
   junction）一律拒绝；否则先移进回收站（可撤销）。台账读改写走**跨进程文件锁**，
    台账写失败只警告、不把已成功的安装判成失败。
    锁的两个坑（都是并发下台账丢条目的成因，已修）：
    - Windows 上"锁文件已被别人打开"不一定报 `EEXIST`，还可能是 `EPERM/EBUSY/EACCES`——
      早先只认 `EEXIST`，把竞争当成"目录不可写"，于是**退化成无锁**跑读改写；
    - 释放锁时只删**自己那一次**持有的锁（锁文件里写 pid + 时间戳 + 随机 token），
      否则被判定 stale 抢占过之后，旧持有者收尾会把别人新拿的锁删掉。
    读台账同理：`EPERM/EBUSY` 是"正在被替换"，要重试；当成坏文件会导致空台账被写回，
    把别人的条目整片抹掉。

导入本地（`import` / `import-upload`）走同一套校验：路径归一化 + 段内字符白名单、
frontmatter 的 `name` 必须合法、目标必须落在技能根内、先复制到技能根之外再复读校验后才落位，
体积上限 20 MiB（单文件 5 MiB、最多 2000 个文件），目标已存在默认拒绝。

其它：

- **回收站可撤销**：删除只是移进 `<DSH_HOME>/skill-manager/trash/`，台账可还原；清空回收站是
  **逐条删**的（每条 5 次退避重试，对付杀毒/索引服务的毫秒级占用），删不掉的条目跳过并留在台账、
  界面用黄字说明"删了几个、哪几个没删掉"，一条失败不连坐整批；目录早就不在的陈旧台账行顺手清掉；
- **覆盖导入不会丢数据，也不怕句柄占用**：导入/覆盖时先在技能根**之外**复制并逐文件校验
  （文件集合 + 字节数），然后**把旧目录改名挪开**、把新的改名进来，最后才删挪开的那份 ——
  热路径上一次删除都不做。为什么不用"先删再改名"：Windows 上刚删掉的目录名会被文件监听/
  句柄咬住（表现为 `EPERM`/`EIO`），而且"先删"一旦后面失败，用户那份技能就没了。
  任何一步失败都会把旧目录改回原位；删除/改名/复制都带重试（`EPERM`/`EACCES`/`EBUSY`/`EIO`）；
- **台账坏了不静默清空**：`market.json` 解析失败会先备份成 `market.json.corrupt-<时间>`，
  界面显示警告，而不是让历史安装记录凭空消失；
- **不静默覆盖、不假装知道**：拿不到会话作用域的注册表快照时，生效状态标为
  `按优先级推算`，而不是谎报"生效/不生效"。

## 已知限制

- 只支持 `.tgz` 包格式；
- 归档路径禁止 `:` 与控制字符（全平台）、Windows 上另外禁止 `< > " | ? *`，
  判重在 Windows/macOS 上大小写不敏感——换来的是"字符串相等 ≈ 文件相同"这个不变式；
  万一还有没想到的别名（例如 8.3 短名在某些卷上成立），第 8、9 步的两次复读会兜住；
- **能写技能根的本地进程可以改安装结果**：那是权限问题，协议层挡不住；
- 拖拽导入要经过浏览器 → Host 传内容，超大技能包请改用"点击选择目录"那条路（不走上传）；
- 设置弹窗里 **`marketUrl` 与技能根是只读的**（改 `cordis.patch.yml` 后重启 Host）；
  工作目录与导入目标可以直接改、会记住；
- 市场默认**关闭**（`marketUrl` 为空），本地管理照常可用；
- 非 Windows 平台只在测试里覆盖（8.3 短名、保留名等行为依赖具体文件系统）；
- 第三方客户端插件拿不到 typert Remote，所以界面与 Host 之间只用同源 HTTP 路由。
- 界面优先用 DSH 的客户端 UI 原子（`@deepseek-ai/dsh-client-ui-primitives`），但**它不是公开 API**：
  DSH 自己的插件编写指引明确要求第三方插件不要 `require` 它（"may change without notice"）。
  本插件是 try/catch 引入、拿不到就退回自带 HTML 版本（按钮层级照抄宿主的
  `--dsw-alias-button-primary-fill` 配方），所以不会因此崩，但换 DSH 版本后控件观感可能与宿主有细微差别。

**详情 facts 行高减半**、**查看 SKILL.md 之后再点变成「收起文件」**、

**市场安装的两步确认**。

其中几条值得一提：

- `test/targz.test.mjs` 会调用系统 `tar`（bsdtar/GNU tar）造**真实** `.tgz`（带目录条目、
  中文文件名）再解包；`test/market.test.mjs` 里还有一条端到端：真实 bsdtar 包 → 真实 HTTP
  市场 → 安装 → 我们的扫描器能扫到它。只用自己的 writer 测是测不出"真实包被误拒"的；
- 渲染测试需要 devDependencies，缺了就自动跳过：`pnpm add -D react react-dom jsdom`。
